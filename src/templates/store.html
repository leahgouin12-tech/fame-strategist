iPhone — parked by you, on purpose

On 2026-11-15 you asked why the app could not simply be downloaded from AltStore, and the answer is that AltStore cannot install itself: something has to sign the build with your Apple ID first, and that something runs on this PC and needs Apple’s device stack under it. Counted as steps, the route costs about a dozen of them plus three installers, which you said was too much for what the Phone page already does in fifteen seconds. So this route is parked, not failed — the build is compiled, the file is here, the listing is live, and everything that is left is yours to do in one sitting whenever you want an app icon that came from a store page instead of the share sheet. Nothing below is a task you have agreed to.

Two separate jobs, and only one of them needs Apple’s tools. Compiling the wrapper is the job a Mac owns; signing it is not. AltStore’s own Windows instructions say AltServer runs on this PC and signs with your Apple ID, so the iPhone half is: build unsigned on a free macOS runner, hand the file to this machine, let AltServer sign it.

  1. Compile, unsigned. .github\workflows\ipa.yml builds ios\ on a free macOS runner with XcodeGen and Apple’s xcodebuild, then zips the built app into FameStrategist.ipa and uploads it as a download. Signing is deliberately turned off in that file because the certificate is yours, not the runner’s. Done: run #6 compiled green on 2026-11-15 and run #7 is the current artifact, both published as fame-strategist-ipa. That build still reports four warnings, and they are honest ones: the icon set has no 1024×1024 or iPad sizes, because the largest real artwork in this project is src/static/icon-512.png and nothing here is going to pretend a blown-up copy is high resolution. iPhone icons install and display fine without them; only an App Store submission would refuse.
  2. Put the file where this page can see it. Unzip the artifact into data\packages. Done: FameStrategist.ipa is in that folder, and this page and the listing both read it from its bytes — the size and the date are measured, never typed.
  3. Install AltServer on this PC. Not done, and this is where the route waits for you. AltStore’s Windows page requires iTunes and iCloud installed directly from Apple (not the Microsoft Store builds), with wifi sync enabled. The three files it needs are already downloaded to data\altstore-setup (iTunes 202 MB, iCloud 161 MB, altinstaller.zip), so no fetching is left. Then you type your Apple ID and password into AltServer — that is your credential and this app never touches it.
  4. Add the source on the phone. Paste the listing URL below into AltStore’s source field, on a phone joined to the same wifi with this laptop awake.
  5. Let it keep itself installed. A personal signature is short-lived, so AltServer refreshes it in the background. How many apps and how many days a given account type allows is carried in AltStore’s own pages and was not verified here.

The one thing nobody has answered yet: every URL in that listing is plain http on your wifi. AltStore’s source documentation never requires HTTPS — it just shows https in its examples and says nothing about a local address — so whether the AltStore app is allowed to fetch a source over plain http is AltStore’s and iOS’s decision, not this file’s. It cannot be settled on paper. The first test of step 4 answers it, and if it refuses, the only fix is hosting the two files somewhere public, which is the thing you said you do not want — then the honest iPhone app stays the home-screen one below.

What is already true today

The Phone page installs this as a home-screen app: Share → Add to Home Screen gives it its own icon, no address bar and its own window, with nothing hosted. That works on your account in the United States, and it is not a store listing.

Apple’s alternative-marketplace rules — Brazil, Japan or the EU, by account region and where the phone physically is — are about installing from a marketplace. AltStore Classic’s path is your own Apple ID signing your own build; the pages read here state no region limit for it.

What has not happened yet

Nothing is installed on a phone, and nothing Apple is installed on this machine — no iTunes, no iCloud, no Bonjour, no Apple Mobile Device Service, no AltServer (checked the same day). The .ipa itself is real and is here: run #6 of the ipa action compiled ios\ for the first time on Xcode 26.6, run #7 is the artifact you downloaded, and the file now sits in data\packages where the table above can see it. The three runs before the green one were red, and each named a defect only a compiler could name: an error constant Apple's enum does not contain, a delegate method labelled with: instead of WebKit's withError: — which compiled and simply never became the delegate, so the “the laptop did not answer” screen would not have appeared — and an Info.plist with no CFBundleExecutable, meaning an app that installs and does not know which file to run. All three are fixed in the source. What is left is not code.

Also still untested, and only testable on the phone: whether AltStore will read a source over plain http at all. That question is parked with the route.

Who can reach this page

The pages that hold your photos and your numbers sit behind the PIN on the Phone page. This one, plus the listing file and the downloads, answers a phone that has not typed the PIN — deliberately, because an installer app cannot carry your cookie and would otherwise fetch nothing. What those three expose to your wifi is the built app and its description; there is no database, no inbox and no key in them.

If you would rather that door stayed shut, delete the files in data/packages — with nothing to hand out there is nothing to reach.

Android — written, parked

You said iPhone only, so this is not a step to do; it is work that already exists and costs nothing to leave alone. apk\ holds the same wrapper as two Kotlin screens — a first-run address box and a WebView with the file chooser, camera grant and download listener wired up — and plain http is allowed only on the private wifi ranges and .local names, so a mistyped address cannot hand your PIN to a captive portal. scripts\make_keystore.ps1 then scripts\build_apk.ps1 would produce a signed APK on this machine, and .github\workflows\apk.yml builds the identical project on a free Linux runner. Nothing has been compiled: there is no JDK, Gradle or Android SDK here, and an APK needs none of Apple’s rules, no review and no region answer — the download itself is the store. It stays here, unused, until an Android phone is actually in the picture.

What this is not. It is not a hosted app. Every package on this page is a window onto this machine: install it on a phone that is not on your wifi, or open it while the laptop sleeps, and it shows you a page that cannot load. That is the same trade the Phone page makes, and it is why a public store listing is only useful to people you have told the address of — the file is installable by anyone, the app works for nobody but you. What is on this page is the listing and the download; publishing to itch.io, Aptoide or AltStore is still your account, your taps and your name, and nothing here does it for you.
